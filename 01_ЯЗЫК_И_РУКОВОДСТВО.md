# Книга 1: Знакомство с MX и первый запуск

Коротко: MX это язык программирования для тех кому надо чтобы всё быстро работало и не
тащить за собой кучу библиотек. По скорости он как C, но писать на нём приятнее. Есть
классы, интерфейсы, дженерики, встроенная графика и 3D. Я пользуюсь им уже давно и могу
сказать точно — для своих проектов больше ничего не подключаю, всё уже внутри.

Сюда я выложил всё что нужно чтобы начать. Дальше пошли подробности.

---

## Установка

Ставить MX проще всего через инсталлер. Ничего собирать руками не надо.

### Windows

Скачай `minimix-installer.exe`, запусти. Он сам скачает нужную версию, распакует и добавит
mx в PATH.

```bat
minimix-installer.exe
```

Если хочешь поставить для всех пользователей — запускай от имени администратора:

```bat
minimix-installer.exe --system
```

Можно самому выбрать папку:

```bat
minimix-installer.exe --dir C:\mx
```

После этого открой новый терминал (старый PATH не подхватит) и проверь:

```bat
mx --version
```

Должно напечатать что-то вроде `MX / MINIMIX 0.2.0`.

### Linux

Скачай скрипт `install_linux.sh` и запусти:

```bash
bash install_linux.sh
```

Он поставит MX в `~/.local/share/minimix` и пропишет его в PATH. Хочешь ситемно — так:

```bash
sudo bash install_linux.sh --system
```

Новый терминал, проверка:

```bash
mx --version
```

Инсталлеры умные: если запустить их повторно, они не налепят дублей в PATH.---

## Первая программа

Создай файл `hello.mx`:

```mx
func main(): int {
    System.println("Привет, MX!")
    return 0
}
```

Запускаем:

```bash
mx hello.mx hello.mxb --run
```

На экране появится `Привет, MX!`. Всё, ты только что написал первую программу.

Что тут происходит:
- `func main(): int` — точка входа, с неё наченается любая программа.
- `System.println(...)` — вывод на экран, println значит «печать + перенос строки».
- `return 0` — говорим системе что всё прошло нормально.

## Способы запуска

У MX есть три варианта запуска, у каждого своя цель.

**1. Интерпретатор — для разработки**

```bash
mx hello.mx hello.mxb --run
```

MX превращает код в байткод и запускает его на своей машине. Быстрее всего проверить, что
всё работает.

**2. Настоящий исполняемый файл — для скорости**

```bash
mx hello.mx hello.exe --aot
./hello.exe
```

Собирается полноценный exe, который бегает на полной скорости процессора и ничего больше
не требует.

**3. JIT — промежуточный вариант**

```bash
mx hello.mx --jit
```

JIT это компиляция на лету. Для быстрых вычислений, когда не хочется думать про сборку.

## Полезные команды

Полный список даёт `mx --help`. Вот основное:

| Команда | Что делает |
|---|---|
| `mx --version` | версия |
| `mx --features` | список возможностей |
| `mx --examples` | примеры команд |
| `mx doctor` | проверка что MX настроен правильно |
| `mx hello.mx hello.mxb --run` | скомпилировать и запустить |
| `mx hello.mx hello.exe --aot` | собрать exe |
| `mx --lang Russian` | справка на русском |
| `mx lsp` | включить помощника для редактора |

---

## Помощник для редактора (LSP)

MX умеет дружить с VS Code. Даёт подсветку ошибок прямо при наборе, автодополнение,
подсказки при наведении и переход к определению. Запускается так:

```bash
mx lsp
```

Для VS Code есть готовое расширение, оно само поднимет MX.
